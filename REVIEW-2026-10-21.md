## Physics & aero

- [ ] 🟡 Aero fit accepts a non-positive CdA on the fixed-Crr path — *added 10/21*
  - Why: `analysis/aero.py` checks `b > 0` only when it fits Crr itself. With Crr held fixed (`b = Σx(y−a)/Σx²`, no plausibility check) messy laps — a mis-linked recording, an e-bike, a badly calibrated meter — fit a negative CdA. `AeroFitRead.cda_m2` has no `ge=0`, so `goals/service.py:_predict` feeds it into `physics.Setup(cda_m2=…)`. Verified end to end: a synthetic session fits CdA −0.0049 and the 4 km goal prediction comes back as 155 s at 39.7 m/s (143 km/h); a CdA of exactly 0 raises in `steady_speed_ms` — now a clear `ValueError` after the physics guard, but still a 500 on the goals endpoint.
  - Notes: apply the same `b > 0` check (plus a sane upper bound, e.g. CdA ≤ 1.0) to the fixed-intercept path in `aero.estimate`, or return `fit=None` when implausible; optionally add `ge=0` to `AeroFitRead.cda_m2` (`aero/schemas.py`) and let the goal prediction degrade to `no_cda`. Tests in `tests/test_aero.py`.

- [ ] 🟢 Add degenerate cases to the shared physics vectors — *added 10/21*
  - Why: the Python/TS mirrors now agree on the guards (both raise / return early) and guard tests exist in `tests/test_physics.py` and `physics.test.ts`, but `shared/physics-test-vectors.json` only covers valid inputs. The vector format has no "raises" case, so this is optional hardening against future drift.
  - Notes: extend `tests/physics_vectors.py` with an error-case format, or leave as is — the unit tests already pin the behavior.

## Security

- [ ] 🟡 Validate the transponder code charset — *added 10/21*
  - Why: `TransponderAssignmentCreate.transponder_code` is only `Field(min_length=1, max_length=255)` (`connections/schemas.py`), and `SqorzHttpClient` interpolates it into `f"{sqorz_base_url}/{code}"`. A code containing `/`, `?`, `#` or `..` makes the backend/worker fetch a different path on my.sqorz.com on every poll, and the code is stored as `external_id` and echoed in the UI/admin.
  - Notes: real codes look like `LS-03407`; add `Field(pattern=r"^[A-Za-z0-9][A-Za-z0-9-]{0,31}$")` (the code is already normalized to uppercase in `connections/service.py`) plus a 422 test. `connections/schemas.py`, `tests/test_connections.py`.

- [ ] 🟢 Pin `FORWARDED_ALLOW_IPS` to the edge container — *added 10/21*
  - Why: prod compose trusts the whole `172.28.0.0/24` compose network, so any process that lands on it (worker, backup, db, a future service) can spoof `X-Forwarded-For` and mint its own rate-limit bucket — the limiter guards login/signup/password-reset.
  - Notes: one line in `docker-compose.prod.yml`: `FORWARDED_ALLOW_IPS: 172.28.0.10/32` (the edge's fixed address). `tests/test_rate_limit_proxy.py` already covers the middleware semantics.

- [ ] 🟢 Refresh-token rotation / revocation — *added 10/21*
  - Why: `/auth/refresh` re-issues but never invalidates the old refresh token, and logout only clears cookies, so a stolen refresh token lives up to 30 days with no revocation short of a password change.
  - Notes: larger and optional — accepted tradeoff of stateless JWTs. `jti` + a small denylist table, or DB-backed refresh tokens with rotation and reuse detection. `core/security.py`, `auth/router.py`.

- [ ] 🟢 Cap decompression in `streams.unpack` — *added 10/21*
  - Why: `zlib.decompress(blob)` has no output limit; the Intervals client already has `gunzip_limited` for the same risk. Blobs are self-written today, so this is hardening, not a fix.
  - Notes: `activities/streams.py`; mirror `gunzip_limited`'s `decompressobj(data, limit + 1)` pattern.

## Input validation & robustness

- [ ] 🟢 Length caps on user-supplied strings — *added 10/21*
  - Why: `SignupRequest.display_name` (`auth/schemas.py`), roster/club `display_name` (`clubs/schemas.py`), bike `name` (`equipment/schemas.py`) and several `notes` fields (`training/schemas.py`) have no `max_length`. The DB columns are `VARCHAR(255)`/`VARCHAR(100)`, so over-long input is a 500 `DataError` rather than a clean 422; `TrainingEvent.notes` is `Text` (unbounded; Caddy caps bodies at 25 MB). Comment bodies (4000) and aero notes (5000) are already capped.
  - Notes: add `Field(min_length=1, max_length=…)` to those fields.

- [ ] 🟢 Disable API docs in prod — *added 10/21*
  - Why: Caddy proxies `/api/*`, so `/api/docs` and `/api/openapi.json` are publicly reachable and hand an attacker the full schema.
  - Notes: env-gated `docs_url=None` in `app/main.py`. Keep `/api/health` public — it is by design (uptime monitors).

  - Why: `e2e/` exists and is green on the dev stack, a local prod stack and the live site, but `.github/workflows/ci.yml` doesn't run it.

  - Why: login/signup limits key on client IP only, so distributed credential stuffing is bounded per-IP. Argon2's cost already helps; a per-email bucket would blunt botnets.
  - Notes: slowapi supports multiple limits per endpoint; `auth/router.py`.

- [ ] 🟢 Frontend shared-vectors import is layout-fragile — *added 10/21*

  - Notes: copy the vectors into the frontend at build time, or check in a fixture.

## Reviewed, no action needed

- Strava webhook POST has no authenticity check when `strava_webhook_subscription_id` is unset — by design (events are hints; destructive actions are re-verified with Strava); rate-limited 120/min, subscription id checked when configured.
